# Agent-Native 设计原则（草案）

> 当你的用户是 Agent，设计的逻辑会彻底改变。

## 1. 文本优先，结构化输出

Agent 读文本，不看像素。所有输出应支持结构化格式（JSON/YAML），所有输入应接受自然语言或标准化参数。

## 2. 可发现性

Agent 应该能自己"发现"你的能力，而不需要提前被告知。`--help`、schema 描述、能力清单——这些是 Agent 时代的"首页"。

## 3. 确定性

同样的输入，同样的输出。Agent 的决策链依赖确定性，模糊的返回值会让整条链路崩溃。

## 4. 可组合性

每个能力都是独立的原子操作，可以被自由组合进任意工作流。不要假设调用顺序，不要隐含前置条件。

## 5. 最小权限

Agent 请求什么权限就给什么权限，不多给。每次操作都应声明所需权限，支持细粒度授权。

## 6. 可逆性

危险操作必须可撤销，或至少要求显式确认。Agent 会犯错，系统应该容错。

## 7. 文档即接口

API 文档、权限说明、调用示例——这些不是附属品，而是产品本身。Agent 通过读文档来"学会"使用你的能力。

*以上原则待持续补充和验证。*
